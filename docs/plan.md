# 実装計画

1. AstroPaper の設定と日本語 Home / ナビゲーション: 主要ページが生成され、GitHub リンクが正しいこと。
2. RDAD / Projects と記事下書き: 原文に基づき、未確認の体験を明示。下書きが公開物に含まれないこと。
3. 配信設定と運用文書: 公式 Action と最小権限、手動実行、記事追加方法を確認。
4. 結合検証: 本番ビルド、ページ・検索・RSS・サイトマップ・URL、下書き除外を確認し、結果と残課題を Tracking Issue に記録。公開承認後に Pages で実機確認。

## 引き継ぎ時の公開準備

1. 原稿2本と元の全履歴を非公開で退避し、SHA-256 と Git bundle を検証する。
2. 現在の tree から原稿を除き、build-only CI と承認 SHA による手動配信の条件を追加する。原稿を除いた本番ビルドと生成物を確認する。
3. 非公開リポジトリで CI を実行し、実測結果を Tracking Issue に記録する。
4. レビュー対象の追跡ファイルから独立した root commit を準備し、全到達可能 object に原稿・旧履歴がないことを検査する。
5. 候補の commit / tree SHA とレビュー項目を人間へ提示する。承認後に [公開準備](publication.md) の順序で移行・Pages 配信・本番検証を行う。

同一問題の修正2回失敗で原因分析へ、統合検証の修正3サイクルで設計前提を再評価する。
